## Une tâche pour exécuter, une dot pour suivre

La tâche de développement conserve le dépôt, le GO, les preuves et le prochain geste concret. Un seul exécutant écrit ; le contre-relecteur reste en lecture seule. La dot suit l’objectif, les décisions groupées et les résultats/blocages, avec un lien vers cette tâche ; elle ne lance pas un second exécutant sur le même lot. Cette étape n’a créé ni configuré de dot ou d’automatisation.

Un objectif utile est défini avec critères, périmètre, exclusions, sources, contre-revue et retour arrière. L’accord groupé nomme les actions couvertes : code/tests, éventuelles exceptions FROZEN précises, commit/push, migrations et livraison privée/recette si incluses. Continuer jusqu’aux critères atteints ; aucune nouvelle demande pour chaque fichier, commande, correction de revue ou reprise déjà couverte. Une action hors GO, une décision métier manquante ou un contrôle humain natif reste un arrêt ciblé, avec raison et preuve.

L’exécutant prépare les propositions et vérifie lui-même le résultat lorsque les outils le permettent. L’opérateur confirme les décisions métier groupées, pas une succession de clics techniques. La démonstration finale présente une cotation enregistrée, relue, versionnée et son PDF. Une recette manuelle nécessaire est annoncée comme telle ; elle ne devient pas une preuve d’automatisation.
